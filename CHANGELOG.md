# AIBL Installer changes

## 2026-09-19

- Six fixes from the first real Mac run of the paste route (a team member on a Homebrew machine, 09-19). None changes the install flow or a pinned guard file.
  - **Guard proof cannot false-pass.** `SETUP-PROMPT.md` step 7 frames the headless test as a deliberate test of the hook, so the model attempts `cat .env` instead of declining on its own judgment before the hook runs. The only pass signal is now the literal `[secrets-guard hook]` tag the guard appends to every refusal; a model refusal without it is named as a fail. The diagnostic check is scoped to the chosen app (`--check --claude`), so a Claude-only student is not told a Codex guard is missing.
  - **A failed tool names its own error.** `course_setup.command()` now appends the tool's last stderr (or stdout) lines to the paused message with the exit code, instead of only our classification. The run that prompted this failed once with "check the network" on a GitHub-side hiccup and left nothing to diagnose; the classification was right, the evidence was hidden. "Rerun the same launcher" becomes "run the same command again".
  - **Any Claude Code install counts.** Step 3 detects the native installer, Homebrew (`/opt/homebrew/bin/claude`, `/usr/local/bin/claude`) and npm locations; 4.4 and 5.3 install only when none was found, so a Homebrew Claude never gets a second copy; the proof runs the `claude` that answered `--version` in 4.6 or 5.5.
  - **Hook commands use the stable Node launcher.** `refresh-guard.mjs` picks `/opt/homebrew/bin/node`, `/usr/local/bin/node` or `C:\Program Files\nodejs\node.exe` when it resolves to the running binary, and passes it to `install.mjs` through the `CLAUDE_HOOK_NODE` seam that file already had, and to the AWS supplements and the Codex launcher. `process.execPath` alone resolves Homebrew's symlink to the versioned Cellar path, which `brew upgrade node` deletes; Claude Code treats a hook that cannot launch as a non-blocking error, so the guard would have switched off in silence. The install output now names the Node path it wrote. Importing the module no longer runs the installer (`pickStableNode` is unit-tested; every written command is asserted to use the picked path).
  - **A "No folder" session continues.** Step 1.5 accepts the home folder or no folder open, since every path in the procedure is absolute; it still stops for a project or cloud-synced folder and says why (the workbench created inside the home folder is already trusted when opened later).
  - **No hunt for a "core version".** Step 10 dropped the phrase; `hub_setup.py` reads the template's `.aibl/template.json` version into the receipt (`template.version`, `null` when the template ships no stamp) and step 8 tells the assistant where to read it.

## 2026-09-11

- Enrollment leaves the installer. The installer builds the Essentials hub for everyone and never asks which program a student is in: `SETUP-PROMPT.md` step 2 drops the program question, step 8 always runs `--course agent-essentials`, `START-HERE.md` and both terminal launchers follow, and the "bundled program not yet" pause is gone because the installer checks only the template. New `scripts/enroll.py` runs later, inside the workbench: it refreshes this checkout, reads the registry, asks GitHub which program repositories the signed-in account can read (a 404 is "not invited"; sign-in and network failures stop plainly and are never read as absence), reports a bundled program as "included, invitation pending" rather than missing, shows the list, asks before doing anything, records the decision in `.aibl/enroll.json`, and names each program's adoption skill. It never touches release pins; adoption stays with `aibl-adopt-workforce`. Re-runnable: an installed program (`.aibl/installed-<product>.json`) is left alone. The registry gains `adopt_skill` per program (`null` means no adoption route yet, so the Lab reports clone-beside for now); `menu` is kept for tooling but the installer no longer reads it. An explicit course argument remains for pinned cohort setups. `tests/test_enroll.py` covers joined, not invited, included-pending, installed, decline, `--yes`, `--check`, `--program`, signed-out, network-down and the CLI. Why: chapter 2 of Essentials has no branch point, every setup recording is program-agnostic, and the ship-day team grants no longer have to precede install.
- Secrets guard for both apps, canonical here. `hooks/refresh-guard.mjs` and the Codex and AWS adapters are ported from `agent-native-os` (its `scripts/refresh-guard.mjs`, `codex-secrets-guard.mjs`, `codex-secrets-tripwire.mjs`, `aws-credential-*.mjs`, and trust manifest), reading the canonical files from this directory instead of downloading a tag, LF-normalized so a Windows checkout installs the exact pinned bytes. Rolled in: the Stripe live-key rule (workshop-installer #17) and the Codex trust-step guidance (agent-native-os #89). The manifest is recomputed for the reviewed bytes; `hooks/manifest.test.mjs` fails CI on drift and `hooks/manifest-regen.mjs` rewrites it inside a reviewed change. The setup prompt installs both guards with one command and proves each by behavior: a headless refusal for Claude, and for Codex the interactive trust screen ("Trust all and continue") followed by a refused `cat .env`, because headless Codex never runs hooks.
- App-first entry. `SETUP-PROMPT.md` returns, rewritten for the program route and both apps: the student opens the Claude or Codex app on their home folder and pastes one prompt; the app audits, explains, installs only what is missing (Git, GitHub CLI, Python, Node, the app's command-line twin, the secrets guard), guides the two browser sign-ins, then runs `course_setup.py --harness <claude|codex> --no-launch` to create the workbench the tested way, and tells the student how to open it in the app. `START-HERE.md` leads with that route; the terminal launchers remain as the fallback and accept `AIBL_HARNESS` / `-Harness`. `course_setup.py` gains `--harness`, Node in the floor, Codex sign-in via `codex login status`, and never hands Codex a slash command. The prompt joins the pinned file set. Codex secrets guard: the prompt installs it when `hooks/codex-secrets-guard.mjs` is present and says so plainly when it is not yet.
- Program registry. `course-options.json` is now `aibl.program-registry/v1`: one line per program with the site ledger's ids (`agent-essentials`, `agent-workforce`, `the-lab`), the publisher repository, what each program requires (checked strictly) and includes (checked softly and reported as found or not yet). The menu is generated from it and asked by `course_setup.py` after tools are ready; the launchers no longer carry a hard-coded menu. The Lab is a program of its own and is included with Agent Workforce. The pinned course id follows the registry (`agent-workforce`); release product ids are unchanged.
- Seeded `aibuild-lab/aibl-installer` from `workshop-installer` at 64130d9 with full history. Removed the legacy Agent Native OS route (install.mjs, install.sh, install.ps1, SETUP-PROMPT.md, MANUAL-INSTALL.md, the migration and repo-prep scripts, their test, and the generated OpenWiki pages); it stays in `workshop-installer`, frozen. The course menu is Essentials and Agent Workforce. Every installer reference now names `aibuild-lab/aibl-installer`, so any existing frozen distribution lock is invalid by design and must be regenerated.
